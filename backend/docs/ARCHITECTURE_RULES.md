# قواعد الهندسة المعمارية لمشروع NGLP Backend

## نظرة عامة
هذا الملف يحدد القواعد الهندسية الصارمة التي سنلتزم بها طوال تطوير مشروع NGLP Backend. هذه القواعد مصممة لضمان كود نظيف، قابل للصيانة، وقابل للتوسع، مع التركيز على أفضل الممارسات في تطوير تطبيقات Spring Boot.

## القواعد الأساسية

### 1. معمارية الطبقات النظيفة (Layered Architecture)
- **Controllers**: طبقة التحكم المسؤولة عن استقبال الطلبات من الـ Frontend وإرجاع الاستجابات. يجب أن تكون هذه الطبقة خفيفة وتركز فقط على التوجيه.
- **Services**: طبقة الأعمال (Business Logic) التي تحتوي على منطق التطبيق الرئيسي. هنا يتم معالجة البيانات وتنفيذ العمليات التجارية.
- **Repositories**: طبقة الوصول إلى البيانات (Data Access Layer) باستخدام Spring Data JPA للتفاعل مع قاعدة البيانات MySQL.
- **Entities**: تمثيل البيانات في قاعدة البيانات

### 2. استخدام قاعدة بيانات MySQL مع Spring Data JPA
- جميع العمليات على قاعدة البيانات ستتم عبر Spring Data JPA.
- استخدام JPQL أو Criteria API للاستعلامات المعقدة.
- تجنب استخدام SQL خام إلا في حالات استثنائية ومبررة.

### 3. فصل البيانات باستخدام DTOs (Data Transfer Objects)
- عدم إرسال الـ Entities مباشرة للـ Frontend لأسباب أمنية وأداء.
- استخدام DTOs لنقل البيانات بين الطبقات والـ Frontend.
- استخدام مكتبات مثل MapStruct لتحويل الـ Entities إلى DTOs تلقائياً.

### 4. توثيق جميع الـ APIs باستخدام Swagger/OpenAPI
- كل API endpoint يجب أن يكون موثقاً بشكل كامل باستخدام Swagger.
- تضمين أمثلة للطلبات والاستجابات.
- استخدام SpringDoc OpenAPI للتكامل مع Spring Boot.

### 5. استخدام Lombok لتقليل الكود المكرر
- استخدام annotations مثل @Data, @Getter, @Setter, @Builder لتقليل الكود المكرر.
- تجنب كتابة getters و setters يدوياً إلا في حالات خاصة.

### 6. معالجة الاستثناءات بشكل مركزي (Global Exception Handling)
- استخدام @ControllerAdvice لمعالجة الاستثناءات عالمياً.
- إنشاء استثناءات مخصصة (Custom Exceptions) لكل نوع من الأخطاء.
- إرجاع استجابات خطأ موحدة ومفيدة للـ Frontend.

## قواعد إضافية
- **التسمية**: استخدام CamelCase للمتغيرات والطرق، PascalCase للكلاسات.
- **التعليقات**: كتابة تعليقات واضحة ومفيدة للكود المعقد.
- **الاختبارات**:Integration Tests.
- **الأمان**: تطبيق مبادئ الأمان من البداية، مثل التحقق من المدخلات (Input Validation).
- **الأداء**: مراقبة الأداء وتجنب العمليات الثقيلة في الـ Controllers.

هذه القواعد غير قابلة للتغيير إلا بموافقة جماعية، وسنراجع الالتزام بها في كل مرحلة من مراحل التطوير.
