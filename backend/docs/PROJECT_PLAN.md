# خطة مشروع NGLP Backend

## نظرة عامة
هذه الخطة تفصل مراحل تطوير Backend لمنصة NGLP، وهي منصة تعليمية تفاعلية مدعومة بالذكاء الاصطناعي. الخطة مقسمة إلى 5 مراحل (Sprints) تعكس معمارية مرنة وقابلة للتوسع، مع التركيز على الجودة والأمان.

## Sprint 1: Core & Data (أساسيات البيانات)
**المدة المتوقعة:** 2-3 أسابيع  
**الهدف:** إعداد الأساسيات للمشروع وإدارة البيانات.

- إعداد مشروع Spring Boot مع التبعيات الأساسية (Spring Web, Spring Data JPA, MySQL Driver, Lombok).
- تكوين قاعدة بيانات MySQL وإعداد الاتصال.
- تصميم وإنشاء الـ Entities الأساسية:
  - User: لإدارة المستخدمين (طلاب، معلمين).
  - Lesson: لإدارة الدروس (مع روابط الفيديوهات).
  - Transcript: لحفظ النصوص المستخرجة من الفيديوهات مع التوقيت.
- إنشاء الـ Repositories باستخدام Spring Data JPA.
- إعداد Global Exception Handling باستخدام @ControllerAdvice.
- كتابة اختبارات أساسية للـ Entities والـ Repositories.

## Sprint 2: Flexible Storage Strategy (استراتيجية التخزين المرنة)
**المدة المتوقعة:** 2-3 أسابيع  
**الهدف:** تطبيق نظام تخزين مرن للفيديوهات.

- تطبيق نمط التصميم Strategy Pattern لرفع الفيديوهات.
- إنشاء StorageService interface مع طرق للرفع، الحذف، والحصول على الروابط.
- بناء LocalStorageServiceImpl للبيئة المحلية (Dev) لحفظ الفيديوهات محلياً.
- بناء CloudinaryStorageServiceImpl للبيئة الإنتاجية (Prod) لرفع الفيديوهات إلى Cloudinary.
- استخدام Spring Profiles للتبديل بين الاستراتيجيات حسب البيئة.
- إنشاء Controllers و Services لإدارة رفع الفيديوهات.
- كتابة اختبارات للـ Storage Services.

## Sprint 3: Whisper AI Pipeline (خط أنابيب Whisper AI)
**المدة المتوقعة:** 3-4 أسابيع  
**الهدف:** دمج نموذج Whisper لمعالجة الفيديوهات.

- برمجة المهام غير المتزامنة باستخدام @Async للتعامل مع الفيديوهات المرفوعة.
- دمج مكتبة Whisper (عبر OpenAI API أو محلياً) لاستخراج النص من الفيديوهات مع التوقيت الزمني (Timestamps).
- حفظ النتائج كـ JSON في قاعدة البيانات MySQL (في جدول Transcript).
- إنشاء Service لإدارة عملية المعالجة وتحديث حالة الدرس.
- معالجة الأخطاء في حال فشل المعالجة (مثل فيديوهات تالفة).
- كتابة اختبارات للـ Async tasks والمعالجة.

## Sprint 4: Spring AI Agent (وكيل Spring AI)
**المدة المتوقعة:** 3-4 أسابيع  
**الهدف:** دمج الذكاء الاصطناعي للتفاعل التعليمي.

- دمج مكتبة Spring AI لبناء وكيل ذكي (AI Tutor).
- استخدام ميزة Function Calling لإعطاء الوكيل أداة برمجية تجلب النص بناءً على توقيت الفيديو.
- برمجة API endpoint يتلقى استفسار الطالب مع التوقيت (مثل: "اشرح هذا الجزء من الدرس في الدقيقة 5").
- توجيه الاستفسار للوكيل الذكي ليقوم بالشرح بناءً على النص المستخرج.
- إنشاء DTOs للطلبات والاستجابات.
- كتابة اختبارات للتفاعل مع الوكيل.

## Sprint 5: Security & Docs (الأمان والتوثيق)
**المدة المتوقعة:** 2-3 أسابيع  
**الهدف:** تأمين التطبيق وتوثيقه.

- تطبيق Spring Security مع JWT Token للمصادقة والترخيص.
- إنشاء endpoints للتسجيل، تسجيل الدخول، وإدارة الجلسات.
- توثيق جميع الـ REST APIs باستخدام Swagger/OpenAPI.
- إعداد الأدوار والصلاحيات (مثل Student, Teacher, Admin).
- كتابة اختبارات للأمان والتوثيق.
- مراجعة نهائية للكود وتحسين الأداء.

## معايير الجودة
- **Code Coverage:** 80% على الأقل للاختبارات.
- **Performance:** استجابة API في أقل من 500ms للعمليات البسيطة.
- **Security:** تمرير فحوصات OWASP الأساسية.
- **Documentation:** توثيق كامل لجميع الـ APIs والكود.

## مخاطر محتملة
- تعقيد دمج Whisper AI: قد يتطلب تعديلات على البنية.
- تغييرات في Spring AI: مراقبة التحديثات والتوافق.
- أداء قاعدة البيانات: تحسين الاستعلامات حسب الحاجة.

هذه الخطة قابلة للتعديل بناءً على المتطلبات الجديدة أو التغييرات في النطاق.
